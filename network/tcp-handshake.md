# 网络：TCP 三次握手，终于记住了

## 过程（客户端视角）

```
客户端                  服务端
  |--- SYN (seq=x) ------->|   1. 我想建连，我的序号是 x
  |<-- SYN+ACK (seq=y, ack=x+1)  2. 好，我的序号是 y，你的 x 收到了
  |--- ACK (ack=y+1) ----->|   3. 你的 y 收到了，建连成功
```

## 为什么是三次，不是两次

两次的话，客户端发的**旧的、延迟的 SYN** 到达服务端，
服务端直接建连并等数据，客户端却不认这个连接——
服务端白白 holding 一个半开连接，这就是 SYN 洪水攻击的原理。

第三次 ACK 让服务端确认"客户端真的想连"，
顺带把序号同步了。

## 四次挥手为啥多一次

建连时 SYN+ACK 可以合并（没数据要发）；
断连时服务端可能还有数据没发完，先回 ACK，
发完数据再发 FIN，所以拆成四次。

## 排查命令

```bash
ss -tan | grep SYN-SENT    # 卡在第一次握手？对端没回
ss -s                      # 看各状态数量，SYN_RECV 暴涨要警惕
```

面试常考，生产上能帮你看懂一半的连接问题。
