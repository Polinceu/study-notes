# JS：事件循环，微任务永远比宏任务先跑

面试常考，本质就一句话：同步代码跑完，先清空微任务队列，再跑一个宏任务，如此循环。

## 看一段代码的输出

```js
console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");
// 输出：1、4、3、2
```

## 为什么是这个顺序

- `1`、`4` 是同步代码，先跑。
- `Promise.then` 是微任务，同步代码一结束就跑，所以 `3` 在 `2` 前面。
- `setTimeout` 是宏任务，要等当前这轮微任务清空才轮到它。

## 实际影响

- `await` 后面的代码也是微任务：`await fetch(...)` 之后的代码不会立刻跑。
- 在微任务里不停产生新微任务会饿死宏任务，页面渲染（也是宏任务）会被拖住。
- `queueMicrotask(fn)` 可以显式把一件事排进微任务队列。
